## Playwright failures — all identical root cause

```
Test timeout of 90000ms exceeded.
Error: page.goto: ... waiting until "networkidle"
```

Failing tests:
- `compose-send.spec.ts:34` — send a mail
- `critical-path.spec.ts:62` — toggle read → unread → read
- `critical-path.spec.ts:93` — toggle flag → unflag
- `critical-path.spec.ts:118` — open first mail in detail view
- `navigation.spec.ts:75` — navigation tour

**The bypass and shell actually work.** Every failing test's page snapshot
shows the authenticated shell rendered — the profile menu displays the test
account and the sidebar is present. The tests do not fail on auth or on
missing UI; they fail because `page.goto` waits for `networkidle`, and the
Blazor WASM client holds persistent connections (SignalR / keep-alive), so
the network never goes idle → 90s timeout on every navigation.

`networkidle` is a documented Playwright anti-pattern for SPA/Blazor apps.

## Suggested fix (test-side, not product code)

Replace `waitUntil: 'networkidle'` with a deterministic wait on a rendered
element, e.g.:

```ts
await page.goto('/Mail')                     // default waitUntil: 'load'
await expect(page.getByRole('menu', { name: 'Profile menu' }))
  .toBeVisible()                             // or a mail-list-specific locator
```

This is a `tests/E2E/` change (owned by the human — `/qa` does not modify the
suite beyond the first-run scaffold), so it is logged here rather than applied.
