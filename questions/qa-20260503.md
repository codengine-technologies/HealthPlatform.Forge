
et :

```

   at UserSettingsRepository.GetOrCreateUserIdAsync() in UserSettingsRepository.cs:line 107
```

**La base Postgres dev locale a encore les colonnes `integer` Identity**, mais le code post-task-020 lit `Guid` partout (entités migrées + EF ValueGenerators câblés). La migration consolidée `20240101_SetupMigration.cs` (édition task-018/019/020 → `AsGuid().PrimaryKey()`) **n'a jamais été rejouée** sur la DB locale.

Le DOD task-020 listait précisément cet item :
> - [ ] **`DROP DATABASE` + replay → toutes les tables Postgres ont `id uuid`**
>       (vérification psql `\d+`)

L'item est resté non-coché (test manuel humain, déféré). Il n'a jamais été fait.

## Fix attendu

```bash
# Drop + recreate dev DB. Aspire ressuscite Postgres au prochain démarrage,
# la migration consolidée se rejoue from scratch.
docker exec -it $(docker ps -q -f "name=postgres") psql -U postgres -c "DROP DATABASE mss_mail;"

# Ou plus radical : drop le container Postgres et laisser Aspire le recréer
docker rm -f $(docker ps -aq -f "name=postgres")

# Puis vérifier le schéma après replay :
docker exec -it $(docker ps -q -f "name=postgres") psql -U postgres -d mss_mail -c "\d Contacts"
# Attendu : colonne Id type uuid (pas integer), colonne UserId type uuid
```

C'est une opération **destructive** (perte des données dev locales — mails, contacts, signatures stockées), donc à faire main par le humain en connaissance de cause.

Une fois la DB rebuilt :
1. Vérifier `\d+ Contacts` → `Id uuid not null`, `UserId uuid not null`
2. Relancer `/qa --headed` → smoke 200 attendu, suite Playwright verte
